精选项目

两个从设计走到可运行的系统，各有一个真正的难点

在线订票系统

演出票务 · 微服务架构 · 选座下单 / 支付回调 / 订单查询

要解决的问题
高峰期大量请求同时涌入选座下单，最直接的后果是座位超卖，以及同一个人重复提交出多张订单。
库存这一层
用 Redis + Lua 脚本把库存校验和预扣减合成一次原子操作，再叠一层 Redisson 分布式锁拦住同一用户的重复提交，座位不会被重复售出。
下单这一层
预扣减完成后接口直接返回，订单落库交给 Kafka 消费者异步完成，接口层只负责库存校验与扣减。
这样换来了
接口响应不再被写库拖住；代价是订单的最终一致要由消费端保证，幂等与补偿得显式设计。

接口层不等待订单写库，落库压力被 Kafka 摊到消费端——这是这套系统最关键的一次取舍。

安卓本地音乐播放器

Kotlin · Jetpack Compose · SD 卡扫描 / 后台播放 / 通知栏控制 / 歌词同步

要解决的问题
播放器最容易散掉的地方是播放状态：界面、后台服务、通知栏各持一份，一暂停就对不上。本地文件来源还很杂，标签和歌词的编码并不统一。
播放链路
用 Service + MediaSession 重构整条链路，把播放状态收在一处，界面只做订阅，通知栏与 App 内控制状态实时同步。
解析这一层
用协程把音频元数据解析与封面解码挪到 IO 线程；自己写了 ID3v2（v2.2 / v2.3 / v2.4）标签解析和 LRC 歌词解析，兼容 UTF-8 / UTF-16 / GBK，并处理了歌词时间轴的对齐。
这样换来了
播放状态只有一份来源，控制不会错位；列表滑动不再被解析阻塞，编码不标准的文件也能对上歌词。
